Motivação

Como combinar um segredo sem se encontrar antes?

Criptografia simétrica

Uma única chave serve para cifrar e para decifrar (ex.: AES).

Problema: a chave precisa chegar ao destinatário por um canal seguro. Se alguém a intercepta, lê tudo.

Criptografia assimétrica

São duas chaves matematicamente ligadas:

  • pública: cifra. Pode ser divulgada a todos.
  • privada: decifra. Fica só com o dono.

Quem intercepta o canal vê a chave pública e o texto cifrado, mas sem a chave privada não consegue decifrar.

O algoritmo

RSA (Rivest, Shamir e Adleman, 1977)

Geração das chaves

  1. Sortear dois primos grandes p e q (1024 bits cada)
  2. n = p · q
  3. λ(n) = mmc(p − 1, q − 1)
  4. Escolher e = 65537 com mdc(e, λ(n)) = 1
  5. d = e⁻¹ mod λ(n)

Chave pública: (n, e). Chave privada: d.

Cifrar (chave pública)

c = me mod n

Decifrar (chave privada)

m = cd mod n

Por que é seguro?

Como e·d ≡ 1 (mod λ(n)), temos (me)d ≡ m (mod n). Calcular d exige λ(n), e calcular λ(n) exige fatorar n. Para um n de 2048 bits, não há algoritmo conhecido que faça isso em tempo viável.

Código 1 · aritmetica.py

Gerando primos de 1024 bits

def miller_rabin(n: int, rodadas: int = 40) -> bool:
    if n < 2:
        return False
    for p in PRIMOS_PEQUENOS:
        if n % p == 0:
            return n == p

    # Escreve n - 1 como d * 2^s, com d ímpar.
    d, s = n - 1, 0
    while d % 2 == 0:
        d //= 2
        s += 1

    for _ in range(rodadas):
        a = secrets.randbelow(n - 3) + 2  # base aleatória em [2, n-2]
        x = pow(a, d, n)
        if x in (1, n - 1):
            continue
        for _ in range(s - 1):
            x = pow(x, 2, n)
            if x == n - 1:
                break
        else:
            return False  # "a" é testemunha de que n é composto
    return True


def gerar_primo(bits: int) -> int:
    while True:
        candidato = secrets.randbits(bits)
        candidato |= (1 << (bits - 1)) | (1 << (bits - 2)) | 1
        if miller_rabin(candidato):
            return candidato

Miller-Rabin

Teste probabilístico: um primo sempre passa. Um número composto passa em uma rodada com chance de no máximo ¼. Com 40 rodadas, a chance de erro fica abaixo de 4−40 ≈ 10−24.

Filtro rápido

Antes do teste, o candidato é dividido pelos primos menores que 2000 (crivo de Eratóstenes). Isso descarta a maioria dos compostos quase de graça.

Bits fixados

Os 2 bits mais altos ficam em 1, o que garante que n = p·q tenha exatamente 2048 bits. O bit mais baixo fica em 1, o que garante um candidato ímpar. O módulo secrets usa o gerador seguro do sistema operacional.

Montando o par de chaves

def construir_chave_privada(p, q, e=E_PADRAO) -> ChavePrivada:
    if p == q:
        raise ValueError("p e q devem ser primos distintos")
    lambda_n = mmc(p - 1, q - 1)
    if mdc(e, lambda_n) != 1:
        raise ValueError("e não é coprimo com λ(n)")
    d = inverso_modular(e, lambda_n)
    return ChavePrivada(
        n=p * q,
        e=e,
        d=d,
        p=p,
        q=q,
        dp=d % (p - 1),
        dq=d % (q - 1),
        qinv=inverso_modular(q, p),
    )

Inverso modular

inverso_modular usa o algoritmo de Euclides estendido: encontra x e y com e·x + λ·y = 1, e então d = x mod λ.

dp, dq, qinv

São valores pré-calculados para o Teorema Chinês do Resto, que deixa a decifragem cerca de 3 vezes mais rápida (próximos slides).

Preenchimento (padding)

Por que não usar o RSA “puro”?

Determinístico

A mesma mensagem sempre gera o mesmo texto cifrado. Um atacante cifra “SIM” e “NÃO” com a chave pública e compara com o que interceptou.

Maleável

Multiplicar c por 2e faz o destinatário decifrar 2·m, e ninguém percebe a alteração.

Mensagens curtas

Se me < n, o “mod n” não tem efeito, e basta tirar a raiz e-ésima de c para recuperar m.

A solução: OAEP (Bellare e Rogaway, 1994)

Antes de elevar a e, a mensagem é misturada com uma semente aleatória de 32 bytes e recebe um hash de verificação. Bloco de k = 256 bytes:

Os 190 bytes vêm de 256 − 2·32 − 2. A semente mascara o DB, e o DB mascara a semente (MGF1 com SHA-256).

Código 3 · oaep.py

Codificação OAEP (RFC 8017 §7.1)

def mgf1(semente: bytes, tamanho: int) -> bytes:
    saida = bytearray()
    contador = 0
    while len(saida) < tamanho:
        saida += HASH(semente + contador.to_bytes(4, "big")).digest()
        contador += 1
    return bytes(saida[:tamanho])


def codificar(mensagem: bytes, k: int, rotulo: bytes = b"") -> bytes:
    if len(mensagem) > tamanho_maximo_mensagem(k):
        raise ValueError("mensagem grande demais para um bloco OAEP")

    l_hash = HASH(rotulo).digest()
    ps = b"\x00" * (tamanho_maximo_mensagem(k) - len(mensagem))
    db = l_hash + ps + b"\x01" + mensagem

    semente = secrets.token_bytes(TAMANHO_HASH)
    db_mascarado = _xor(db, mgf1(semente, k - TAMANHO_HASH - 1))
    semente_mascarada = _xor(semente, mgf1(db_mascarado, TAMANHO_HASH))

    return b"\x00" + semente_mascarada + db_mascarado

MGF1

“Estica” um valor curto até o tamanho desejado, concatenando SHA-256(semente ‖ 0), SHA-256(semente ‖ 1) e assim por diante.

Decodificação

Desfaz os dois XORs e confere: o 1º byte é 00, o lHash bate, o PS só tem zeros e existe o separador 01.

Erro genérico

Qualquer falha gera o mesmo ErroDecifragem("falha na decifragem"). Se o programa dissesse qual verificação falhou, um atacante poderia usar isso para decifrar a mensagem (ataque de Manger, 2001).

Código 4 · rsa.py

Cifragem e decifragem

def rsaep(chave: ChavePublica, m: int) -> int:
    """Primitiva de cifragem: c = m^e mod n."""
    return pow(m, chave.e, chave.n)


def _rsadp_crt(chave: ChavePrivada, c: int) -> int:
    m1 = pow(c, chave.dp, chave.p)
    m2 = pow(c, chave.dq, chave.q)
    h = (chave.qinv * (m1 - m2)) % chave.p
    return m2 + h * chave.q


def rsadp(chave: ChavePrivada, c: int) -> int:
    """m = c^d mod n, com blinding."""
    while True:
        r = secrets.randbelow(chave.n - 2) + 2
        if mdc(r, chave.n) == 1:
            break
    c_cego = (c * pow(r, chave.e, chave.n)) % chave.n
    m_cego = _rsadp_crt(chave, c_cego)
    return (m_cego * inverso_modular(r, chave.n)) % chave.n


def cifrar_bloco(chave: ChavePublica, bloco: bytes) -> bytes:
    k = chave.tamanho_bytes
    em = oaep.codificar(bloco, k)
    c = rsaep(chave, bytes_para_int(em))
    return int_para_bytes(c, k)

pow(m, e, n)

O pow do Python faz exponenciação modular rápida (quadrados sucessivos): cerca de 2048 multiplicações em vez de 65537.

CRT (Teorema Chinês do Resto)

Em vez de uma exponenciação módulo n (2048 bits), o código faz duas módulo p e q (1024 bits cada) e junta os resultados com a fórmula de Garner. É cerca de 3 vezes mais rápido.

Blinding

c é multiplicado por re, com r aleatório, antes de usar a chave privada, e o fator r é removido no final. O tempo de cálculo deixa de depender do c que o atacante escolheu, o que protege contra ataques de temporização.

Código 5 · rsa.py

Mensagens de qualquer tamanho

def cifrar(chave: ChavePublica, mensagem: bytes) -> bytes:
    k = chave.tamanho_bytes
    limite = oaep.tamanho_maximo_mensagem(k)
    pedacos = [mensagem[i : i + limite] for i in range(0, len(mensagem), limite)]
    if not pedacos:
        pedacos = [b""]  # mensagem vazia também vira um bloco válido
    return b"".join(cifrar_bloco(chave, p) for p in pedacos)


def decifrar(chave: ChavePrivada, cifrado: bytes) -> bytes:
    k = chave.tamanho_bytes
    if not cifrado or len(cifrado) % k != 0:
        raise ErroDecifragem("falha na decifragem")
    blocos = [cifrado[i : i + k] for i in range(0, len(cifrado), k)]
    return b"".join(decifrar_bloco(chave, b) for b in blocos)


def cifrar_texto(chave: ChavePublica, texto: str) -> str:
    return base64.b64encode(cifrar(chave, texto.encode("utf-8"))).decode("ascii")

Divisão em blocos

Um bloco de 2048 bits comporta no máximo 190 bytes. Uma mensagem de 1000 bytes vira 6 blocos cifrados de 256 bytes cada.

Texto: UTF-8 e Base64

O texto é convertido em bytes UTF-8, o que suporta acentos e emoji. O resultado é codificado em Base64 para poder ser copiado e colado como texto.

No mundo real

Usa-se criptografia híbrida: o RSA cifra só uma chave AES aleatória, e o AES cifra os dados (como no TLS e no PGP). Aqui usamos o RSA diretamente porque esse é o objetivo do trabalho.

Experimente

RSA de livro-texto no navegador

Versão simplificada, com primos pequenos e sem OAEP, que cifra cada byte separadamente. Repare que bytes iguais geram o mesmo texto cifrado: esse é o problema que o OAEP resolve.

Decisões técnicas

Segurança: o que foi feito e o que falta

Implementado

  • OAEP + SHA-256: cifragem aleatória e com verificação de integridade
  • secrets: aleatoriedade criptograficamente segura
  • Chaves de 2048 bits (recomendação do NIST); mínimo de 1024
  • e = 65537; p e q distantes (contra o método de Fermat)
  • Blinding contra ataques de temporização
  • Erro genérico contra o ataque de Manger
  • Validação da chave carregada; segredos fora do repr

Limitações (projeto didático)

  • Python puro não garante tempo constante. Em produção, use bibliotecas auditadas, como cryptography e OpenSSL.
  • Não usamos criptografia híbrida (RSA + AES), que é o padrão para dados grandes.
  • A chave privada é salva sem senha. O ideal seria usar PKCS#8 com cifragem.
  • O programa não faz assinatura digital, então não há autenticação do remetente.
